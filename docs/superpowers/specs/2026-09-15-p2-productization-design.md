# P2 产品化设计附录：Onboarding 自动化 + 内置训练场

日期：2026-09-15
状态：已定稿
基线：P1.5 已交付（专业化前端 + 多段 AI 引擎）

## 背景

用户反馈两条：① 需要内置训练场（类似 Aim Lab 的瓦专项内容）；② 产品流程不完整——用户进来应知道这是什么、该怎么用，能自动化的流程全部自动化，只需通知用户且可取消。

## 1. 产品流程：Onboarding + 自动化 + 通知

### 1.1 首次进入向导（Onboarding）

- 本地应用不做账号密码系统，"登录"语义 = 绑定游戏身份（昵称#数字ID）
- 首次访问（无绑定身份）进入全屏向导：
  1. **是什么**：产品定位一句话 + 三大能力图示（对局分析 / 风格定位 / 训练闭环）
  2. **绑定身份**：输入昵称#ID，验证存在性；Windows + WeGame 环境下预留"自动检测本机身份"入口
  3. **自动化授权**：一句话说明"之后新对局会自动分析并通知你"，开关默认开，可关
- 完成后跳 Dashboard；`onboarded` 标记存后端（不是 localStorage，换浏览器也不丢）
- 各页面空态统一改为引导态（"先去绑定身份"按钮回顾向导）

### 1.2 自动化引擎

- 后端后台轮询器（asyncio task，可配置间隔，默认 5 分钟）：拉取绑定玩家最新对局 → 发现新 match_id → 自动完成深度分析 → 写通知
- 自动化开关存 config.json（`automation: {enabled: bool, poll_interval_min: int}`），设置页可改
- 演示通道（fixture）：提供 dev 端点模拟"新对局到达"，让自动化链路在 mock 下可演示

### 1.3 通知中心

- 通知模型：`{id, type, title, body, link, read, created_at}`，SQLite 持久化
- API：GET /api/notifications（含未读数）、POST /api/notifications/{id}/read、POST /api/notifications/read-all
- 前端：顶栏铃铛 + 未读红点 + 下拉面板，点击通知跳对应页面；自动化动作（新分析完成、复测提醒）都产生通知

## 2. 内置训练场

### 2.1 定位

把训练计划里的外部依赖（Aim Lab 任务）逐步替换为产品内置科目，成绩入库进入复测闭环。网页 Canvas 实现，Valorant 专项设计。

### 2.2 首发三科目

1. **爆头线定位（Headline Flick）**：目标只出现在屏幕爆头线高度带内的随机水平位置，点击命中；测平均反应+命中率。对应"aim"维度
2. **反应速度（Reaction）**：画面变色/目标出现后尽快点击，测毫秒级反应。对应"duel"维度
3. **跟枪追踪（Tracking）**：目标平滑变速移动，准星持续压在目标上累计命中时间占比。对应"aim/stability"

### 2.3 训练场框架

- Canvas 游戏引擎基建：倒计时、命中判定、成绩计算、结果页（本次成绩 vs 历史最佳 vs 段位基准）
- 每个科目一局 30-60 秒，结束出成绩卡
- API：GET /api/training/scores（按科目分组的历史）、POST /api/training/scores（{drill, score, extra}）
- 训练页改造：新增"内置训练"分区（三科目入口 + 各科最近成绩/最佳成绩迷你趋势）；计划中的任务可直接跳对应科目

## 3. 边界

- 视觉复盘（demo 录屏 + VLM）仍不在本期
- 账号系统不做（本地应用）；WeGame 自动检测为预留入口，真机联调时接
- P2 技术债顺带处理：LLM 调用合并（analyze_match 与 analyze_deep 重叠）与批量评分接口
