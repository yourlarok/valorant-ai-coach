# 无畏契约 AI 对局教练 — 设计文档

日期：2026-09-15
状态：已定稿，待实施计划

## 1. 需求背景

做一个针对无畏契约（国服为主）的 AI 对局分析工具，类似"LOL AI 对局分析"：

1. 战绩查询（拉取玩家对局历史）
2. 对局内个人行为优劣分析（全局 + 针对指定玩家）
3. 问题点 + 改进计划（含 Aim Lab 等瞄准训练推荐）
4. 视觉级复盘（基于回放 demo 的视频理解）
5. 风格定位与评分系统（有趣、有话题性、可分享）
6. 训练闭环：诊断 → 处方 → 执行 → 复测验证 → 调整处方

## 2. 关键约束与红线

### 数据源合规

- 国服没有官方开放 API 或插件授权体系。唯一可行路径：用户本机 WeGame 登录态（cookie/token）调 WeGame 内部接口（参考 valorant-cn-stats-query 项目模式）。
- 凭证纯本地保存，绝不上传；不做远程 token 推送类功能。
- **只分析本人及同场公开可见数据。不做任何绕过"隐藏战绩/不允许查看"隐私开关的功能。** 这是写入规格的硬红线。
- 数据层设计为可替换适配器：WeGame 接口失效时可换源（如腾讯未来开放接口、国际服 HenrikDev API）。

### 依赖稳定性

- WeGame 内部接口随时可能变动或封禁，采集器需做好失败降级与提示。
- 国服回放系统（2025-10 上线）：客户端"生涯"页可下载 demo 文件（支持一般/竞技/超速冲点/Premier），本地存放、可分享。demo 为 Riot 私有格式，无成熟公开解析器，不直接解析二进制，走"客户端播放回放 + 录屏"路线。

### 算力

- 分析引擎全部走云端大模型 API（OpenAI 兼容接口，用户填自己的 key）：文本分析用 LLM，视频理解用多模态模型。
- Aim Lab 无公开 API，训练执行情况以对局数据复测为准，不对接训练软件分数。

## 3. 产品形态与总体架构

本地 Web 应用（一键启动，浏览器访问），全部数据本地存储。

```
┌─────────────────────────────────────────────┐
│  本地 Web UI（深色电竞风 SPA）                 │
│  首页风格卡 │ 战绩列表 │ 单场报告 │ 视频复盘 │ 训练计划 │
├─────────────────────────────────────────────┤
│  后端服务（Python FastAPI + SQLite）           │
│  ┌──────────┐ ┌──────────┐ ┌─────────────┐  │
│  │ 数据适配器 │→│ 分析引擎  │→│ 风格/训练生成│  │
│  │ WeGame   │ │ LLM 文本  │ │ 规则库+LLM   │  │
│  │ Demo管理 │ │ VLM 视觉  │ │             │  │
│  └──────────┘ └──────────┘ └─────────────┘  │
├─────────────────────────────────────────────┤
│  外部依赖：WeGame 登录态 │ 游戏客户端回放 │ 云端 API │
└─────────────────────────────────────────────┘
```

## 4. 模块设计

### 4.1 数据适配器

**WeGame 采集器**
- 本机专用 Chrome 保存 WeGame 登录态，调用其内部接口。
- 输入 `昵称#数字ID`，拉取近期对局列表与单局 10 人详情。
- 产出**标准化 Match JSON**（自定义 schema，与数据源解耦）：对局元信息、比分、10 人记分板、KDA/ACS、爆头率、武器/技能数据、回合结果、经济数据、段位/RR。

**Demo 管理器**
- 扫描本地回放文件夹，按对局元信息与 Match JSON 匹配。
- 探索生涯页 demo 下载接口，实现"分析时自动下载"；不可行则引导用户手动下载。

### 4.2 分析引擎

**文本分析器**
- Match JSON → prompt 模板 → LLM → 结构化分析结果：
  - 全局总结（局势走向、关键回合）
  - 指定玩家优劣（带数据引用，如"爆头率 12%，低于钻石段位中位数"）
  - 问题点清单（瞄准、对枪、经济、技能、意识等维度）

**视觉分析器**（二期）
- 录屏视频 → ffmpeg 按回合切片（用 Match JSON 回合时间轴对齐）→ VLM 逐片段分析：
  - 准星摆放、预瞄位置、走位选择、技能使用时机、被击杀场景还原
- 输出带时间戳的行为观察，与文本分析交叉验证，作为问题点的视频证据。

### 4.3 风格定位与训练计划生成器

**能力量化（底层，不直接外露）**

六维能力模型，每维 0–100 分，以同段位玩家数据分位数映射（"62 分 = 超过同段位 62% 的人"）：

| 维度 | 数据来源 |
|---|---|
| 瞄准能力 | 爆头率、各武器爆头率、击杀效率 |
| 对枪能力 | 首杀/首死比、正面对枪胜率、多杀回合占比 |
| 意识与站位 | 被侧身/背身击杀占比（视觉复盘补强）、残局胜率 |
| 经济管理 | eco 局起枪合理性、连败经济处理、装备利用率 |
| 技能运用 | 技能击杀/助攻占比、技能浪费率（视觉复盘补强） |
| 稳定性 | 近 N 场 ACS/KDA 方差、神鬼波动幅度 |

综合评分 = 六维加权（权重可配置），S/A/B/C/D 评级。基准库初期用经验值冷启动，随采集数据积累换成本段位真实分布。每次复测生成快照，形成时间序列。

**风格定位（上层呈现，玩家实际看到的东西）**

1. **打法原型（Archetype）**：数据特征 → 风格标签，电竞梗命名，如：
   - 爆头机器 / 开局敢死队 / 老六本六 / 经济黑洞 / 残局之神（之亡）/ 人形闪光弹
   - 每份报告产出 1 个主原型 + 若干副标签，配 LLM 生成的毒舌教练锐评金句。
2. **职业哥定位**：玩家数据特征与职业选手风格模板做相似度匹配（"你的打法画像最接近 aspas 式激进决斗者"）。初期人工定义风格模板，后期可用赛事数据。
3. **分享卡片**：一键生成竖版分享图——称号 + 职业哥定位 + 风格雷达图 + 锐评金句 + 角落 S/A 评级，适合发群/朋友圈。

**训练计划生成器**
- 问题点 → 规则库映射 + LLM 润色 → 具体训练科目：
  - 瞄准问题 → Aim Lab（Sixshot/Microshot 等）/ KovaaK's 具体任务、游戏内 Range 流程、死斗要求
  - 预瞄问题 → 具体地图爆头线练习点位
  - 经济/意识问题 → 规则清单 + 对局内自查项
- 按周排计划，任务可打卡。

**训练闭环（执行情况判定）**

1. 打卡记录（辅助，用户手动确认）
2. 周期性数据复测（核心）：一至两周后重新分析近期对局，对比前后指标（爆头率、首杀胜率、ACS）
3. 录像对比（二期）：前后录像同类行为（如拐角预瞄）变化对比
4. 复测结果驱动处方调整，形成滚动循环；趋势曲线标注训练周期区间

## 5. 视觉复盘流程（二期核心）

1. 报告页点"视觉复盘" → Demo 管理器匹配/下载 demo → 引导用户在客户端回放中播放并录屏（提供一键录制脚本，OBS 或无畏时刻）
2. 视频回传应用 → 按回合自动切片 → VLM 逐片段分析
3. 报告页"问题点 ↔ 视频证据"双向跳转，点击问题点直接回放对应片段

长期探索项：demo 二进制直接解析（暂无公开解析器，不投入）。

## 6. 前端设计

- 深色电竞风 SPA（Vue 3 + ECharts），参考 tracker.gg / 游戏内生涯页视觉语言
- 首页：风格称号大字 + 分享卡片预览 + 六维雷达图（雷达图是卡片元素，不是主角）
- 报告页：单场分析 + 问题点卡片（带视频证据跳转）
- 趋势页：六维分数与综合评分时间曲线，标注训练周期
- 训练计划页：当前处方 + 打卡 + 复测对比

## 7. 技术选型

- 后端：Python + FastAPI + SQLite
- 前端：Vue 3 + ECharts（深色电竞主题）
- 视频处理：ffmpeg；录屏：OBS / 游戏内无畏时刻
- LLM/VLM：OpenAI 兼容可配置接口（用户自填 key）
- 采集：本机 Chrome + WeGame 登录态
- 交付：一键启动脚本，纯本地运行

## 8. 分期交付

- **P1（MVP）**：WeGame 采集 + 标准化 Match JSON + 文本分析 + 六维评分 + 风格定位 + 分享卡片 + 训练计划 + 基础前端
- **P2**：Demo 管理 + 回放录屏流程 + VLM 视觉复盘 + 视频证据联动
- **P3**：自动化打磨（demo 自动下载、对局结束自动分析）、基准库真实分布校准、职业哥模板数据化

## 9. 错误处理与边界

- WeGame 登录态失效 → 明确提示重新登录，不静默失败
- 接口字段变动 → 采集器 schema 校验 + 版本标记，失败时保留原始响应便于排查
- 云端 API 不可用/key 未配置 → 报告页降级为纯数据展示（无 AI 分析）
- demo 缺失或无法匹配对局 → 视觉复盘入口置灰并说明原因
- VLM 观察置信度低（画面模糊/切片错位）→ 标记"低置信"，不作为问题点依据
